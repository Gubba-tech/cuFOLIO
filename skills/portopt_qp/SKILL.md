# PortOpt QP Skill

Use cuFOLIO as the implementation scaffold. Use the PortOpt paper and `Gubba-tech/PortOpt_IPCA` code as the mathematical source for objectives, constraints, regularization, max-Sharpe reparameterization, and factor mapping.

## Rules

- Implement production GPU QP solves with NVIDIA cuOpt.
- Do not call CVXPY or OSQP inside the cuOpt QP backend.
- Do not silently fall back to CPU when `backend="cuopt"`.
- Always pass variable bounds explicitly. Do not rely on cuOpt defaults, because default-bound behavior can vary by API/version and portfolio QP variables may require negative lower bounds.
- Use OSQP only for explicit CPU validation tests and benchmarks.
- Do not claim speedups unless they were generated by benchmark scripts and saved as CSV artifacts.
- Keep cuFOLIO's existing Mean-CVaR LP workflow intact.

## Required Checks

### No uv Found on HPC

Check Python first:

```bash
python --version
```

cuFOLIO requires Python `>=3.11`. If `uv` is missing, install it user-local:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv --version
```

Alternative:

```bash
python -m pip install --user uv
export PATH="$HOME/.local/bin:$PATH"
uv --version
```

If system Python is polluted by broken `pyarrow` / `pandas` packages:

```bash
export PYTHONNOUSERSITE=1
unset PYTHONPATH
```


## Workflow

1. Compile portfolio math into `CompiledQP`.
2. Confirm the objective convention is `0.5 * x.T @ Q @ x + q.T @ x`.
3. For cuOpt, map to `x.T @ Q_cuopt @ x + c.T @ x` with `Q_cuopt = 0.5 * Q`.
4. Always pass variable bounds explicitly. Do not rely on cuOpt defaults, because default-bound behavior can vary by API/version and portfolio QP variables may require negative lower bounds.
5. Add equality, lower-bounded, upper-bounded, and two-sided row constraints from the compiled row-bound form.
6. Extract raw `x`, status, objective value, solve time, max constraint violation, and variable values by name.
